# Engine–Narrative Integration Rewrite

## Contract

- Status: Verified within the automated integration contract. The original migration has been expanded by the [Narrative-native generation reconstruction](narrative-native-reconstruction.md): all thirty-three Map Types own typed native grammars, invariants and operational relaxation policies rather than relying on the earlier abbreviated programme/adaptor layer. The complete corpus, all-33 audit, reviewed baselines, rendered interface, production, Pages and Node 24 Alpine matrix pass. Human Identity Lab evidence and representative real Civ V loads remain separate empirical gates.
- User outcome: Every Narrative Map Type should remain recognisable while looking as though it was produced by the selected Generation Engine's own method. Physical must remain causally physical, Eccentric must remain graph-composed, Excogitare must remain field-grown and Polis must remain strategically authored.
- Scope: Controlled experiments across all four engines and all thirty-three current Narrative Map Types; raw-versus-realized intervention measurements where the former architecture exposed that boundary; final-map structural measurements; a neutral narrative-constraint contract; engine-specific adapters; semantic evaluation; migration order; diagnostics; and verification gates.
- Failure behavior: A narrative request that cannot coexist with explicit settings or Civ V legality must weaken transparently according to a recorded relaxation order. It must not be rescued by an undisclosed post-generation topology replacement.
- Exclusions: The rewrite does not claim physically perfect climate simulation, mathematical multiplayer balance, blind recognisability without Lab evidence, or Civ V runtime compatibility from a self-parse alone.

## Original completion gates

These gates record the approved migration contract. Their current disposition appears later in this document; planning-tense language here is historical rather than a claim that implementation has not begun.

1. **Contract:** Record the distinction between engine causality, narrative identity, explicit controls and final legality.
2. **Data model:** Specify a deterministic, versioned, engine-neutral constraint program with hard requirements, weighted preferences, tolerance, scale interpretation and relaxation order.
3. **Domain behavior:** Define how all four engines consume the same semantic request natively and how semantic objects such as enclosed seas, straits, isthmuses, ranges, watersheds and strategic corridors are evaluated.
4. **Interface:** Specify truthful generation diagnostics and weakened-identity disclosure without adding more first-level Create controls.
5. **Rendering:** Inapplicable to this planning phase; the later implementation must preserve existing 2D, layer and export rendering.
6. **Editing/history:** Specify retained constraint evidence and deterministic regeneration consequences for Refine, Iterate and protection.
7. **Import/export:** Project files must retain programs, adapter diagnostics and evaluation evidence; ordinary `.Civ5Map` output remains tile geography.
8. **Validation/Repair:** Narrative scoring must remain separate from Civ V legality. Repair must not silently manufacture narrative identity.
9. **Verification:** Run reproducible current-state experiments, define unit/property/regression/visual/Identity Lab gates, and record runtime budgets.
10. **Documentation:** Produce the detailed plan with measured findings, limitations and a complete catalogue migration matrix.
11. **Reconciliation:** Compare the experiment, plan, register and current code before marking the planning phase Specified.

## Evidence status

The experiment distinguishes facts available at the raw engine boundary from inferences made from final maps. Phase 1 retains equivalent read-only raw-native, narrative-realized, legality-normalized and final observations for all four engines. The optional snapshot callback returns defensive copies, so an observer cannot mutate generation.

The reproducible harness is [`../../scripts/audit-engine-narrative-integration.ts`](../../scripts/audit-engine-narrative-integration.ts). [`../../scripts/render-engine-narrative-contact-sheet.ts`](../../scripts/render-engine-narrative-contact-sheet.ts) renders fixed four-stage visual fixtures for two seeds and sizes per engine. The complete findings, architecture, catalogue matrix and migration sequence are recorded in the [`Engine–Narrative Integration Plan`](../engine-narrative-integration-plan.md), while [`../narrative-semantic-contracts.md`](../narrative-semantic-contracts.md) freezes the hard relationships, soft preferences and relaxation order for all thirty-three Map Types.

The baseline experiment generated all thirty-three Map Types across two fixed Tiny-map seeds and a focused twelve-type Standard-map set. The expanded Phase 1 run found average post-engine topology replacement of 34.80% for Excogitare, 33.84% for Eccentric and 28.16% for Physical, against 0% for Polis. These figures justify the plan; they do not by themselves verify human recognisability or visual naturalness.

The pre-reconstruction representative game-payload hashes recorded observation of the former architecture; they were not expected to remain unchanged when a native grammar deliberately changed geography. Generated project state still round-trips retained evidence, history cloning remains alias-safe and all four stages have deterministic fingerprints. The final behavior and deliberate geography changes have now been reviewed: the current contact sheet has hash beginning `7ec925…`, and the final retained baseline has digest beginning `e6dae37…`. These current values supersede the old payloads without erasing their historical role.
